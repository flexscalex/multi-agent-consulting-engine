# Engagement brief

One brief per project. The whole engine reads this file first. Keep it tight and factual. Do not put your own strategy in here; if you have one, put it under "Client context" so the lenses know it is your current framing and not a fact.

## Mode

takeover | greenfield

Takeover: a prior team (or a prior you) already collected data and formed opinions. The engine inherits the data, quarantines the opinions, and lets the facts pick the route.
Greenfield: nothing exists yet. The engine builds the fact base from sources.

## The decision

One paragraph. What decision does the client need to make, by when, and what happens if it is made wrong.

## Client context (current framing, open to challenge)

What the client currently believes they are building, who the customer is, how it makes money, what is in and out of scope. State it plainly. The lenses will treat this as the client's starting position, not as a fact.

## Inputs to inherit (takeover only)

- Project folder: absolute path
- Read first: the files a newcomer should read in order (README, HANDOVER, methodology notes)
- Extra inputs outside the folder: memory files, exported chats, Drive docs (absolute paths)
- Data assets: where derived outputs live, where raw pulls live, which folder to trust
- Known-wrong or superseded material: anything the prior team already retracted, so it is not re-inherited

## What to quarantine (takeover only)

Describe the kinds of statements that count as prior opinion. Give three to five verbatim examples from the inherited material so the readers recognize the pattern. Facts underneath an opinion stay; the opinion goes.

## What complete looks like

What data pools, sources, and measurements would need to exist for the fact base to be complete enough to decide. The completeness analyst ranks gaps against this list.

## Constraints the client will not move on

Only true hard constraints (legal, capital, time, ethics). Anything softer belongs in Client context.

## Output

- Output folder: absolute path (usually <project>/engine)
- Who reads it: the client only, or the client plus named collaborators. Affects nothing in the engine but tells the partner who the audience is.
- Anything that must not appear in the output (names, emails, client data that should stay out of a shared repo)
